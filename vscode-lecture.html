    📥 VS Code 다운로드 & 설치

    Visual Studio Code는 전 세계 개발자가 가장 많이 쓰는 가볍고 강력한 코드 편집기입니다. 본인 운영체제에 맞는 버전을 공식 홈페이지에서 받아 설치하세요.

    STEP 05

    🐍 Python 가상환경 (.venv)

    가상환경은 프로젝트마다 라이브러리를 따로 담는 "독립된 상자"입니다. A 프로젝트의 패키지와 B 프로젝트의 패키지가 서로 충돌하지 않게 해 주죠. 실무에서 거의 필수입니다.

    1) Python 설치 확인

    먼저 python.org에서 Python을 설치합니다. Windows 설치 시 'Add Python to PATH' 체크는 반드시! 그 후 VS Code 터미널에서 버전을 확인합니다.

    📚 참고 — PATH란?

    터미널에서 python이라고 입력하면, Windows는 어느 폴더에 있는 python.exe를 실행해야 하는지를 찾아야 합니다. 이때 길을 알려 주는 것이 PATH입니다.

    PATH는 Windows가 프로그램을 찾을 폴더 목록입니다. 예를 들어:

    C:\Windows\System32
C:\Program Files\Python312
C:\Program Files\Git\cmd
...

    Python 설치 시 'Add Python to PATH'에 체크하면 Python 폴더가 이 목록에 자동 추가됩니다. 체크 안 하면 터미널에서 python을 입력해도 "찾을 수 없습니다" 오류가 납니다.

    요약: PATH = "이 폴더들에서 프로그램을 찾아라"는 지도. 체크 필수!

    terminal
    $ python --version
# macOS / Linux 에서는 보통:
$ python3 --version

    2) 작업 폴더 만들고 VS Code로 열기

    .venv는 프로젝트 폴더 안에 생성됩니다. 프로젝트마다 독립된 환경을 가지므로, 먼저 작업 폴더를 만들고 VS Code로 열어야 합니다.

    1. 탐색기에서 빈 폴더를 하나 만듭니다 (예: my-project).
    2. VS Code 실행 → 메뉴 [파일] → [폴더 열기] (Ctrl+K 다음 Ctrl+O) → 방금 만든 폴더 선택.
    3. 처음 열면 "이 폴더의 작성자를 신뢰하시겠습니까?" 창이 뜹니다 → [예, 신뢰함] 클릭.
    4. 터미널 열기: 메뉴 [터미널] → [새 터미널] (Ctrl+`). 터미널이 그 폴더 경로에서 열립니다.
    💡 핵심 .venv는 프로젝트 폴더마다 따로 만들어야 합니다. A 프로젝트와 B 프로젝트는 각자의 .venv를 가집니다.

    3) 가상환경 생성 (.venv)

    VS Code 터미널에서 아래 명령을 입력하면 현재 폴더 안에 .venv가 만들어집니다.

    terminal
    # 'python -m venv [폴더이름]' — 관례상 폴더명은 .venv
$ python -m venv .venv
# macOS / Linux: python3 -m venv .venv

    4) 가상환경 활성화 (Activate)

    운영체제마다 명령이 다릅니다. 활성화되면 터미널 줄 앞에 (.venv)가 표시됩니다.

    terminal
    # Windows (PowerShell)
$ .venv\Scripts\Activate.ps1

# Windows (cmd)
$ .venv\Scripts\activate.bat

# macOS / Linux
$ source .venv/bin/activate

# 활성화 성공 → 줄 앞에 (.venv) 표시됨
(.venv) $
    ⚠️ PowerShell 실행 정책 오류 Windows에서 Activate.ps1 실행 시 "스크립트를 실행할 수 없습니다" 오류가 나면, 관리자 PowerShell에서 아래를 한 번 실행하세요.
    PowerShell (관리자)
    $ Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

    4) 패키지 설치 & 기록

    활성화된 상태에서 pip로 패키지를 설치하고, 목록을 requirements.txt에 저장합니다.

    terminal (.venv 활성화 상태)
    (.venv) $ pip install requests
# 설치된 패키지 목록을 파일로 저장
(.venv) $ pip freeze > requirements.txt
# 나중에 다른 곳에서 똑같이 복원할 때
(.venv) $ pip install -r requirements.txt
# 가상환경 끄기
(.venv) $ deactivate
    💡 VS Code 인터프리터 연결 Ctrl+Shift+P → Python: Select Interpreter → 방금 만든 .venv를 선택하면, 새 터미널이 자동으로 가상환경을 활성화해 줍니다.

    STEP 06

    🟢 Node.js 설치

    Node.js는 브라우저 밖에서 JavaScript를 실행하는 런타임입니다. Live Server, Prettier, 각종 프론트엔드 도구가 모두 Node 생태계 위에서 돌아가므로 설치해 두는 것이 좋습니다.

    1) 설치 — 두 가지 방법

    • 방법 A (간단) · nodejs.org에서 LTS 버전 다운로드 후 설치
    • 방법 B (추천) · 버전 관리자 nvm으로 여러 Node 버전을 자유롭게 전환

    2) nvm으로 설치 (버전 관리에 유리)

    terminal
    # macOS / Linux — nvm 설치
$ curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
# 터미널 재시작 후 최신 LTS 설치 & 사용
$ nvm install --lts
$ nvm use --lts

# Windows 는 'nvm-windows' (별도 프로그램) 설치 후
$ nvm install lts
$ nvm use lts

    3) 설치 확인

    terminal
    $ node -v     # 예) v22.x.x
$ npm -v      # 예) 10.x.x  (Node와 함께 설치됨)

    4) 프로젝트 초기화 & 패키지 설치

    npm은 Python의 pip에 해당하는 패키지 관리자입니다. package.json이 가상환경의 requirements.txt처럼 의존성을 기록합니다.

    terminal
    # 프로젝트 폴더에서 package.json 생성
$ npm init -y
# 패키지 설치 → node_modules 폴더에 담김
$ npm install express
# 스크립트 실행
$ node app.js
    🔁 venv ↔ npm 비교 .venv / node_modules = 격리된 패키지 상자 · requirements.txt / package.json = 의존성 명세서. 둘 다 보통 .gitignore에 폴더는 제외하고, 명세서만 Git에 올립니다.

    STEP 07

    💻 VS Code 터미널 & CLI

    지금까지 친 python·npm·git 명령은 모두 터미널(CLI)에서 실행한 것입니다. VS Code 안에서 터미널을 쓰면 편집 화면을 벗어나지 않고 명령어를 바로 실행할 수 있어 작업 효율이 크게 올라갑니다.

    1) 내장 터미널 열기

    • 단축키 · Ctrl+` (숫자 1 왼쪽 물결 키, Windows·macOS 공통)
    • 메뉴 · 상단 [터미널] → [새 터미널]
    📂 위치가 중요 내장 터미널은 기본적으로 현재 열린 폴더에서 시작합니다. 그래서 .venv 만들기나 git init 같은 명령이 바로 그 프로젝트에 적용됩니다.

    2) 기본 셸(Shell) 선택

    컴퓨터 환경에 따라 터미널 엔진(셸)을 골라 쓸 수 있습니다.

    • Windows · PowerShell, Command Prompt(cmd), Git Bash
    • macOS · zsh, bash
    • 변경 · 터미널 오른쪽 위 + 옆 아래 화살표(∨) → 기본 프로필 선택
    💡 Git 명령에는 Git 명령어를 쓸 땐 Git Bash(Windows)나 zsh(macOS)를 추천합니다. STEP 08의 브랜치·머지 명령이 더 매끄럽게 동작합니다.

    3) 터미널에서 VS Code 열기 — code 명령

    일반 터미널(cmd·macOS 터미널)에서 명령어 한 줄로 폴더나 파일을 VS Code로 바로 열 수 있습니다.

    terminal
    $ code .              # 현재 폴더를 VS Code로 열기
$ code 파일명.txt       # 특정 파일을 VS Code로 열기
    ⚠️ macOS에서 code가 안 먹힌다면 VS Code에서 Ctrl+Shift+P → Shell Command: Install 'code' command in PATH 를 한 번 실행해 주세요.

    4) 알아두면 좋은 기본 이동 명령

    터미널에서 폴더를 오가는 최소한의 명령입니다. 앞으로 모든 실습의 기초가 됩니다.

    terminal
    $ pwd          # 현재 위치 확인 (Windows cmd: cd)
$ ls           # 폴더 안 목록 보기 (Windows cmd: dir)
$ cd myfolder  # 폴더 안으로 이동
$ cd ..        # 상위 폴더로 이동
$ clear        # 화면 정리 (Windows cmd: cls)

    STEP 08

    🐙 Git & GitHub 소스 관리

    AI에게 코딩을 맡기기 전에 반드시 갖춰야 할 안전망입니다. Git이 있어야 AI가 코드를 망쳐도 과거로 되돌리고, 실험을 분리하고, 잘 된 결과만 골라 합칠 수 있습니다.

    핵심 개념 — 한 문장 정리

    📦

    Git (깃)

    내 컴퓨터 안에서 소스코드 변경 내역을 기록·관리하는 버전 관리 프로그램. 게임의 세이브포인트를 만드는 것과 같습니다.

    ☁️

    GitHub (깃허브)

    Git으로 기록한 파일을 인터넷에 올려 보관·공유하는 원격 저장소 웹사이트. 백업이자 협업 공간입니다.

    1) Git 설치 & 첫 세팅

    git-scm.com에서 설치한 뒤, 커밋에 남길 이름과 이메일을 한 번만 등록합니다.

    terminal
    $ git --version
$ git config --global user.name "내이름"
$ git config --global user.email "my@email.com"

    2) 프로젝트에 Git 적용 (초기화 → 첫 커밋)

    내 프로젝트 폴더를 VS Code로 연 뒤, 저장소를 만들고 첫 세이브포인트를 찍습니다.

    terminal · 프로젝트 폴더
    # .venv, node_modules 등은 추적 제외
$ echo ".venv/" >> .gitignore
$ echo "node_modules/" >> .gitignore

$ git init                # 저장소 생성
$ git add .               # 변경 파일 담기
$ git commit -m "first commit"  # 세이브포인트!
    🖱️ VS Code GUI로도 가능 왼쪽 Source Control 패널(Ctrl+Shift+G)에서 메시지를 적고 Commit 버튼만 눌러도 똑같이 동작합니다.

    3) GitHub에 올리기 (원격 연결 & push)

    GitHub에서 빈 저장소(Repository)를 새로 만든 뒤, 그 주소를 내 프로젝트에 연결합니다.

    terminal
    $ git remote add origin https://github.com/내아이디/저장소.git
$ git branch -M main
$ git push -u origin main   # 인터넷에 업로드

    4) AI가 코드를 망쳤을 때 되돌리기 ↩️

    AI(Claude Code, Copilot 등)가 쓴 코드가 마음에 안 들면 Git의 세이브포인트로 돌아갑니다.

    • 아직 커밋 전 · Source Control에서 파일 옆 Discard Changes(둥근 화살표) → 마지막 커밋 상태로 복구
    • 이미 커밋한 경우 · 아래 명령으로 최근 커밋 1개를 통째로 취소
    terminal
    # 가장 최근 커밋 1개 취소 + 코드 되돌리기
$ git reset --hard HEAD~1
    ⚠️ --hard 주의 --hard는 변경 사항을 되돌릴 수 없게 지웁니다. 살리고 싶은 작업이 섞여 있지 않은지 먼저 확인하세요.

    5) AI 협업의 정석 — 브랜치(Branch) 🌿

    안전하게 AI에게 코딩을 시키려면, 메인 코드를 건드리지 않는 독립된 작업 공간(가지)을 만들어 실험합니다.

    🛠️ 1단계 · 새 브랜치 만들어 작업
    terminal
    # main을 보호하며 새 가지를 뻗어 그 안으로 이동
$ git checkout -b feature/ai-coding
    이제 feature/ai-coding이라는 안전한 방에서 AI와 마음껏 코드를 수정하면 됩니다.
    🤝 2단계 · 성공했을 때 (병합 Merge)
    terminal
    $ git checkout main            # 메인으로 이동
$ git merge feature/ai-coding  # 작업 내용 합치기
$ git branch -d feature/ai-coding # 끝난 가지 삭제
    🗑️ 3단계 · 실패했을 때 (폐기 Delete) 코드가 엉망이라 쓸 수 없다면 그 방을 폭파(삭제)하면 됩니다. 메인 코드는 전혀 타격이 없습니다.
    terminal

    STEP 09

    ✨ Claude Code for VS Code

    Claude Code는 VS Code 안에서 Claude가 직접 파일을 읽고·수정하고·실행해 주는 AI 페어 프로그래밍 확장입니다. 코드를 따로 복사해서 옮길 필요 없이, 편집기 안에서 변경 사항을 diff(차이)로 검토하고 수락/거절할 수 있습니다.

    ⚠️ 사전 준비 VS Code 1.98.0 이상 버전과 Claude Pro / Max / Team / Enterprise 중 하나의 구독이 있는 Anthropic 계정이 필요합니다. ( [도움말] → [정보] 에서 버전 확인 )

    1) 확장 설치

    • Extensions 패널 열기 · Ctrl+Shift+X
    • 검색창에 Claude Code 입력
    • 반드시 게시자가 Anthropic인 공식 확장을 선택 (비공식 모방 확장 주의!) → Install
    • 설치되면 사이드바에 Spark 아이콘(✨)이 나타남

    2) 로그인 (인증)

    처음 한 번만 Anthropic 계정으로 로그인합니다.

    • 사이드바의 Spark 아이콘(✨) 클릭 → Claude Code 패널 열림
    • Sign in 클릭 → 브라우저에서 continue in browser 진행
    • 브라우저에서 Anthropic 계정으로 로그인 후 Authorize(승인) 클릭
    • VS Code로 돌아오면 채팅 패널이 활성화 — 로그인 완료!
    🔧 터미널 방식도 가능 CLI를 선호한다면 내장 터미널(Ctrl+`)에서 claude 명령을 실행하는 방법도 있습니다. CLI는 npm으로 설치하며, 이때 STEP 06에서 깐 Node.js가 그대로 쓰입니다.
    terminal (선택 · CLI 방식)
    # Node.js가 설치된 상태에서
$ npm install -g @anthropic-ai/claude-code
# 프로젝트 폴더에서 실행 → 브라우저 로그인 진행
$ claude

    3) 내 프로젝트에서 시작하기

    핵심은 "폴더(워크스페이스)를 먼저 연다"는 것입니다. Claude Code는 열려 있는 폴더 전체를 프로젝트 맥락으로 읽습니다.

    • [파일] → [폴더 열기] 로 내 프로젝트 폴더를 연다 (예: 앞서 만든 .venv 프로젝트)
    • Spark 패널에서 작업을 한국어로 자연스럽게 요청
    • 특정 파일을 콕 집을 땐 @파일명 으로 멘션 (선택한 줄 범위도 가능)
    • 제안된 변경은 diff로 검토 후 수락(Accept)/거절(Reject)
    🧪 Plan Mode (초보 추천) 바로 코드를 고치기 전에 Plan Mode로 "무엇을, 왜 바꿀지" 계획을 먼저 검토하고 승인할 수 있습니다. "측정은 두 번, 자르기는 한 번" 방식이라 실수가 줄어듭니다.
